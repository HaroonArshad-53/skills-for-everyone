# Resume Builder

## When to use this skill
- Making a first resume from scattered notes
- Tailoring a resume to a specific job description
- A resume gets no replies and needs an honest audit

## Workflow
1. Collect the raw material: education, jobs and internships with dates, projects, skills, certifications. Ask for the target job description if one exists - tailoring beats generic.
2. Audit honesty first: list every claim that needs proof (numbers, titles, tools). Anything the user cannot back up in an interview gets softened to the true version or removed.
3. Structure for ATS: standard headings (Summary, Experience, Projects, Skills, Education, Certifications), no tables, no graphics, no text in headers or footers, job-title keywords from the target description used only where they are true.
4. Rewrite bullet points as Action + Task + Result. Where no number exists, use a true scope word (team size, number of users, frequency) instead of inventing a percentage.
5. Order for the reader: fresh graduates lead with Projects and Skills, experienced users lead with Experience. Certifications with exact names and dates as issued.
6. Run the final checklist: contact details present, dates consistent, file named Firstname-Lastname-Resume.pdf, one consistent tense, no spelling errors, nothing the user cannot explain line by line.

## Rules - never break these
- Never invent a job, degree, certification, date, tool, or metric. This rule has no exceptions - a caught lie ends candidacies.
- Keywords from a job description are used only where the user real experience matches. Keyword stuffing a false skill is inventing experience.
- Keep the user real voice in the summary - professional and specific, not dynamic, passionate, result-oriented individual.
- Two pages maximum for early-career users unless their real experience genuinely needs more.

## Output format
- The resume - clean, ATS-structured text ready to paste into a document
- Tailoring notes - which keywords from the job post were matched, and where
- Honesty audit - claims softened or removed and why
- Before you send - filename + 3-point final checklist

## Example
**User:** Make my resume from these notes and tailor it to this SOC analyst job post. Notes and job post pasted by the user.

**Good output (excerpt):** Bullet rewritten truthfully: before - Responsible for security monitoring. After - Monitored sign-in and endpoint alerts during internship shifts; escalated 2 confirmed phishing incidents to the senior analyst with evidence preserved. No metric invented; scope and action made it strong.
