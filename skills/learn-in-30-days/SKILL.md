# Learn Anything in 30 Days

## When to use this skill
- Learning a new skill for a job, freelancing, or exams
- A roadmap is needed that fits real daily hours
- Previous self-study failed because the plan was unrealistic

## Workflow
1. Set the contract first: the exact skill, the user current level (true zero, some basics, intermediate), target outcome in one sentence (hold a conversation, build a portfolio project, pass the exam), and real hours per day. Plans are built from these numbers only.
2. Divide 30 days into 4 weekly stages: Week 1 Foundations (core concepts, small daily wins), Week 2 Guided Practice (following structured material, replicating examples), Week 3 Independent Practice (original small tasks without tutorials), Week 4 Project and Test (one portfolio-sized output and a timed self-test).
3. Each day gets ONE main task completable in the stated hours, with the resource type to use (official docs section, one video lesson, textbook chapter, exercise set) - specific enough to start without deciding anything.
4. Put the self-test at the end of each week (questions or a task done without help) and a rest or light day each week. A plan with no rest day is a plan to quit in week 2.
5. Add the if-you-fall-behind rule: drop the optional tasks marked optional, never the weekly project or test. Show what Week 1 looks like in full; summarise weeks 2-4 by day themes if the user wants the short version.
6. End with the tracking method: a simple daily checkbox list and the weekly question - could I do this week test without help? If no, repeat the week, which is progress, not failure.

## Rules - never break these
- Never plan more hours than the user stated. A 1-hour-a-day plan that survives beats a heroic 6-hour plan that dies on day 4.
- Resource types and official sources only unless a specific resource is verified - never invent course names, links, or book titles.
- The target outcome decides the content. Exam plans drill past-paper style questions; portfolio plans build artefacts. Never give both the same plan.
- 30 days creates a foundation and proof of work, not mastery - say this honestly in the plan intro.

## Output format
- Your contract - skill, level, target outcome, hours per day
- 4 weekly stages - theme + outcome of each week
- Day-by-day plan - one main task per day, resource type, optional tasks marked
- Weekly self-tests - the exact test for each week
- If you fall behind - what to drop, what never to drop

## Example
**User:** I want to learn Python for freelancing, I know zero, I have 1.5 hours a day, in 30 days I want one small project done.

**Good output (excerpt):** Week 4 project scoped to the contract: a file-organiser script the user can demo to clients - not build a web app. Day 1 task: install Python and write a program that renames one file; small, finished, motivating. Daily load never exceeds the stated 1.5 hours.
